# v10.0.52 간결한 기체·장비와 기능 분화

## 미술 교정

사용자가 복잡한 디테일을 거부했다. 실제 참고 화면 `F:/NKW/App/PuzzleKnight/work/UI 샘플 1/보관함 - 장비.jpg`, `보관함 - 부품.jpg`를 다시 확인했다. 형태·대표 색·큰 특징으로 식별하는 원칙을 차용하며 원작 그림을 복제하지 않는다.

- 기체3종과 조립 부품12칸: `assets/art/airframe_v52/`. 기존 외형 비례·부착 좌표를 유지하면서 패널선·볼트·환기구·다중 소켓 테두리를 제거했다. 조립 부품11종과 미사용 어댑터1칸이다.
- 장비32종: `assets/art/gear_v52/basic.png`12종, `boss.png`20종. 주무장·센서·코어·선체·벨트·추진기의 각 spec마다 독립 그림이다. 보스 장비는 세계별 큰 문양 하나와 장갑/노즐 형태를 구분한다.
- 내장 image_gen을 사용했다. 최종 프롬프트·원본명은 각 폴더 `generation.json`, 알파 기반 원본 좌표·해시는 `manifest.json`에 기록한다. 생성 PNG를 재도색/자동 보정하지 않았다.
- 상세했던 이전32종은 `.local/gear-v52/rejected-detail/`에 미채택으로 보관했다. 투명화 재시도는 원본에도 이미 알파가 있음을 확인해 미사용했다. 미리보기 RGB 광채와 실제 알파를 구분했다.
- 공유 `GearArt`가 보관함·장착·상세·보상·성장·보스 장비와 기체 조립에 연결된다. 기체 렌더러도 새 원본만 로드한다. 외부 원본을 런타임에서 참조하지 않는다.

## 저장·호환

보유 spec·아이템ID·강화·정련·잠금·장착ID를 그대로 쓴다. `Profile.aircraftAssembly`의 gearSpecs는 장착 데이터에서 파생한다. 기본 조립 저장에 소유 데이터를 중복 기록하지 않는다. 출격 체크포인트는 당시 장착6종과 발동 횟수/대기/비행 중 로켓을 저장해 재개한다. 구 전투의 필드 누락은 빈 장비/기존 동작으로 복구한다.
