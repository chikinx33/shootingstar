# Shootingstar 온라인 v4

공개 게임: https://shootingstar-online.chikinx1.workers.dev

## 사용 흐름

1. 기존 PC 진행을 이전하려면 `PLAY_SHOOTINGSTAR.cmd`로 **기존 주소 http://127.0.0.1:8787**을 열고 우측 상단 사람 아이콘 → 가입 → 현재 진행으로 계정 만들기.
2. 복구 코드를 별도로 보관한다. 이메일을 수집하지 않으므로 비밀번호 재설정은 복구 코드로 한다.
3. 다른 기기의 웹 주소에서 동일 아이디/비밀번호로 로그인한다. 중단 전투는 같은 기기·브라우저에만 보관하며 먼저 이어서 정산하거나 포기한 뒤 기기를 바꾼다. Android APK 빌드 금지는 유지한다.
4. 성장 → 길드에서 창설 또는 6자리 코드 가입. 출석·기여·토벌·보급은 계정 단위 서버 데이터다.
5. 오프라인 변경은 기기에 보관한다. 두 기기가 각각 변경했다면 계정 화면에서 서버/이 기기 진행을 선택한다. 자동 합산하지 않는다.

로그아웃은 미전송 진행의 동기화/충돌 해결 후 가능하다. 로그아웃하면 계정 진행을 로컬 백업하고 이전 게스트 진행으로 돌아간다. 전투 도중에는 원격 프로필을 적용하지 않고 귀환 후 동기화한다. 실시간 협동 전투는 제공하지 않는다.

v10.0.26: 중단 전투가 있으면 계정 전환/로그아웃을 차단하고 이유를 표시한다. 계정의 `저장·복구 도움말`에서 기기 저장과 영구 진행 동기화, 복구 코드, 저장 실패 대응과 제한된 진단 정보 복사를 제공한다. 진단 정보는 자동 전송하지 않는다.

`계정 영구 삭제`는 정확한 아이디와 현재 비밀번호를 다시 요구한다. 서버 `/api/auth/delete`는 세션 인증·요청 제한·비밀번호 verifier 확인 뒤 조건부 DELETE한다. 계정·세션·저장 이력·길드 개인 기록은 기존 외래 키로 함께 제거된다. 확인 응답 후 기기의 현재 진행·중단 전투·출격 기록·계정/이관 임시 백업을 정리하고 새 게스트 상태로 돌아간다. 다른 기기의 로컬 저장과 공유 길드 집계는 유지한다. 기기 정리 실패 시 서버 삭제 성공과 기기 정리 실패를 구분해 알린다. 외부 삭제 요청 URL과 운영 지원은 `STORE_RELEASE_CHECKLIST.md`의 미완료 조건이다.

## 배포 구조

- Cloudflare Worker `shootingstar-online`: Flutter 정적 파일 + `/api/*` JSON API, 기본 HTTPS 주소.
- D1 `shootingstar-online`, UUID `23e84574-ab75-4689-9f78-22a7ee6623d7`, APAC.
- 사용자 계정, 세션, 버전별 진행, 길드/멤버/보고/보상 테이블. 변경 직전 프로필 최근 5버전은 `save_history`에 보존한다.
- 일일 cron `17 19 * * *` UTC: 만료 세션·요청 제한 버킷 삭제.
- 독립 D1을 새로 만들었고 기존 다른 앱의 DB, DNS, 사용자 도메인은 변경하지 않았다.
- 유료 플랜 변경·구독·도메인 구매는 하지 않았다. 계정의 현재 요금제 조회 권한이 없어 정확한 계정별 청구액은 확인하지 못했다. 실제 청구는 기존 Cloudflare 플랜과 계정 전체 사용량에 따른다.

## 인증과 저장

- 아이디 4~24자 영문 소문자·숫자·밑줄, 닉네임 1~16자. 공식 클라이언트 비밀번호 12~128자.
- 클라이언트 PBKDF2-SHA256 600,000회, 고유 128비트 salt. 서버는 전송된 키의 salted SHA-256 verifier만 저장한다. 전송 키도 비밀번호와 같은 비밀이므로 TLS 필수. 클라이언트의 연산 비용을 사용해 Worker에서 매 인증마다 고비용 연산하지 않는다.
- 웹: HttpOnly / Secure / SameSite=Strict 쿠키. 네이티브: OS 보안 저장소(flutter_secure_storage). D1에는 세션 원문 대신 해시만 저장한다. 30일 만료, 계정당 최근 10세션.
- 192비트 일회용 복구 코드. 복구 시 코드와 비밀번호 정보를 교체하고 기존 세션을 해제한다. 복구 코드와 비밀번호 둘 다 분실하면 앱에서 복구할 수 없다.
- same-origin 검사, JSON 타입/크기 제한, 바인딩 SQL, 인증 시도 및 사용자 요청 제한.
- `cloud/write`는 revision 조건부 UPDATE. 충돌은 HTTP 409로 서버 진행과 버전을 반환한다. 미전송 로컬 진행을 자동 덮어쓰지 않는다.
- 기존 v3 저장 키 유지, 내부 snapshot v4. 계정 교체 시 이전 계정의 업적/테크 세트를 초기화하여 섞이지 않게 한다.
- 로컬 `online.backup.guest`, `online.backup.<account-id>`, `online.backup.conflict-device/cloud` 백업은 SharedPreferences에 보관한다. 개발자 복구용이며 별도 복원 UI는 없다. 앱/브라우저 데이터 삭제 시 로컬 백업도 삭제된다.
- 전투와 보상 경제는 여전히 클라이언트 계산이다. 서버는 길드 출석·코인·보상 지급과 보고 횟수/재전송만 검증하며 완전한 치트 방지가 아니다. 유료 경제/경쟁 랭킹 도입 전 별도 서버 권위 검증이 필요하다.

## 개발·배포

```powershell
.\tools\run.ps1 test
.\tools\run.ps1 build-web
# 게임 완성 전 Android APK 빌드는 하지 않는다.
Set-Location server
npm ci
npx wrangler d1 migrations apply shootingstar-online --local
npx wrangler dev --port 8789
# 다른 터미널, server 디렉터리
npm test
# 일반 웹테스트는 프로젝트 루트에서 python tools/quick_web.py --deploy를 사용한다.
# 아래 명령은 이미 검증한 정식 build/web의 업로드만 필요할 때 사용한다.
# 기존 D1은 유지한다. 스키마 변경 없는 패치에서 원격 마이그레이션은 실행하지 않는다.
npm run deploy
```

웹 빌드 중 Wrangler dev는 정적 파일 삭제/재생성 때문에 종료될 수 있다. 빌드 완료 후 다시 실행한다. `ONLINE_API` dart-define을 지정하면 API 주소를 바꿀 수 있다. 기본 웹은 같은 출처, Android는 공개 HTTPS 주소다.

로컬 실행기 `tools/play_web.py`는 정적 파일을 기존 주소에 제공하고 API만 공개 Worker로 HTTPS 중계한다. 원본 요청 출처를 검사하며 임의 사용자 URL로 프록시하지 않는다. `--online-api http://127.0.0.1:8789`로 독립 개발 DB에 연결할 수 있다. 이전 SQLite 파일은 보존했고 `--legacy-guild`는 v3 API 재현용이다. 익명 길드 회원을 새 계정으로 자동 이전하지 않는다.

## 검증

- Flutter 기존 50개 + 저장/동기화 6개 + 계정 모바일 화면 1개.
- 로컬과 공개 Worker HTTP 통합 테스트: 계정 분리, 2세션 동시 저장(200/409), 2계정 공동 길드, 중복 출석/일일보급 방지, 일일 보고 3회 제한, 복구 후 세션 폐기, 복구 코드 재사용 거절, HttpOnly 쿠키, 잘못된 Origin/JSON 거절.
- 360px 계정 로그인/가입/복구/충돌 선택 화면 overflow 없음.
- 실제 브라우저 공개 로그인 → 클라우드 저장 완료, 길드 참여 → 출석 반영 확인.
- 공개 사이트와 별도 loopback 출처의 독립 저장소에 같은 계정으로 로그인. 서버 저장 버전 2와 543 크레딧을 두 번째 저장소에서 불러오는 것을 UI로 확인.
- 공개 API D1 health 및 공개 main.dart.js SHA-256과 로컬 산출물 일치 검증. 결과: `tools/qa/evidence/online-v4/`.
- Android debug APK 빌드 성공. Android 실기기와 두 물리적 기기의 플레이 검증, 서명 release 배포는 미실시.
