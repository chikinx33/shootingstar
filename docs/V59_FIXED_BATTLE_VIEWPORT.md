# v10.0.59 전투 화면 순간 이동 교정

## 재현된 원인

320×568 실제 BattleScreen 위젯에서 적 출현 안내를 켜면 전장 사각형이 `(0,171)–(320,568)`에서 `(0,207)–(320,568)`로 바뀌었다. 안내가 헤더 Column에 추가되면서 전장이36px 밀리고 축소됐다. 이때 `viewportHeight`와 카메라 원점도 바뀌므로 기체와 배경이 순간적으로 튄다. 이전 패치의 무장 반동/레벨업 섬광 교정과 별개인 레이아웃 문제다.

보스 체력/공격 안내와 특화·연계·파일럿 상태도 같은 헤더에 조건부로 삽입되고 있었다. 적의 일반 생성·처치 자체는 카메라 위치를 변경하지 않는다.

## 변경

- 헤더에는 고정된 항로/시간/체력/경험치/장착 슬롯을 둔다.
- 적 출현/보스 접근 안내와 보스 체력·공격/특화·연계·파일럿 상태는 `Positioned` 오버레이로 분리한다. `IgnorePointer`로 조종 입력을 가로채지 않는다. 정보와 상세/통계 접근은 유지한다.
- 체력/경험치 문구는 글자 배율에 따른 두 줄 높이를 확보해 숫자 증가로 전장 높이가 변하지 않게 한다. 글자 축소·잘라내기는 사용하지 않는다.
- 피해 때의 실제 피격 반응과 보스 격파 후 의도된 출발 연출, 전투 규칙·적 수·보상·자동 저장 주기는 유지한다. 근거 없이 프레임 성능 최적화로 범위를 넓히지 않는다.

## 집중 검증

`test/battle_viewport_stability_test.dart`: 수정 전 안내 표시에서36px 변동을 재현했다. 수정 후 안내 표시/종료, 일반 적 생성/처치, 특화 상태, HP/레벨 숫자 증가, 보스 접근/등장/공격 안내 변화/처치 모두 전장 사각형·viewportHeight·카메라·플레이어 위치가 불변이다.

기존 HUD 검사는 안내가 전장 내부 오버레이에 있다는 계약으로 갱신하며,320px 글자1.3 한 조건을 확인한다. 빠른 웹 검사의 선택형 정상 속도180프레임 표본도 확인한다. 전장 경계는 위 실제 위젯의 렌더 좌표로 검증한다. 웹의 전투 영역 Semantics가 별도 DOM 접근성 노드로 노출되지 않아 DOM 경계 측정은 사용하지 않는다. 이 짧은 표본으로 후반/모든 기기의 프레임 지연이 사라졌다고 주장하지 않는다.

APK는 빌드하지 않는다. 실제 결제·광고 ID 연동은 이번 범위에 없다.
