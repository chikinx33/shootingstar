# 기체 · 파츠 · 모듈 시스템 설계서 (Codex 구현용)

> 이 문서가 플레이어 기체 구성에 관한 **유일한 기준**이다.
> 기존의 "장비 슬롯 6개 / 무장·방어 슬롯 6개 / 지원 슬롯 3개" 구조는 **폐기**하고 이 문서의 구조로 대체한다.
> 수치는 모두 **예시값**이며 밸런스 조정 대상이다. 구조와 규칙은 바꾸지 않는다.

## 0. 한 줄 요약

**기체 = 주포 + 궁극기 + 고정된 모듈 자리. 나머지는 전부 파츠.**
**파츠는 "무엇을 쏘는가", 모듈은 "어디서, 어떻게 쏘는가"를 정한다.**

같은 파츠라도 어느 모듈에 붙이느냐에 따라 발사 방향·발사 수·연사·공격력·폭발 범위가 달라진다.
파츠의 기본 속성(탄 종류, 속성, 유도 여부 등)은 절대 바뀌지 않는다.

게임 장르: 사방에서 적이 몰려오는 서바이버류(예: 탕탕특공대) + 비행 슈팅.
그래서 **모듈 위치 = 어느 방향을 커버하느냐**가 핵심 선택이 된다.

---

## 1. 왜 기존 구조를 버리는가

기존에는 세 시스템(장비 / 조립 파츠 / 지원 파츠)이 각자 슬롯을 갖고 같은 위치(날개, 후방, 추진기 등)를 공유했다.
그 결과 "슬롯 수 ≠ 화면에 보이는 부품 수 ≠ 실제 기능 수"가 되어 구조가 읽히지 않았다.

새 구조는 **시스템이 하나**다. 기체 위의 위치 하나 = 모듈 하나 = 파츠 하나.

## 2. 핵심 개념 4개

| 개념 | 영문 키 | 설명 | 탈부착 |
|---|---|---|---|
| 기체 | `Airframe` | 고유 주포, 궁극기, 기본 스탯, 모듈 배치를 가진 비행기 | 기체 자체를 교체 |
| 모듈 | `Mount` | 기체에 고정된 파츠 장착 자리. 위치별 **성능 배율(프로파일)** 을 가짐 | 고정 (움직이지 않음) |
| 파츠 | `Part` | 모듈에 붙였다 떼는 무기·보조 부품. 각자 레벨을 가짐 | 자유롭게 탈부착 |
| 장착 구성 | `Loadout` | "어느 기체의 어느 모듈에 어느 파츠"인지 저장한 데이터 | — |

## 3. 기체 (Airframe)

기체만 가진 고유 요소. **파츠로 만들 수 없고, 탈착 UI에도 나타나지 않는다.**

1. **주포** — 수직 전방(화면 위쪽)으로 쏘는 기본 총알. 기체마다 다름.
2. **궁극기** — 에너지를 모아 쓰는 기체 고유 기술. 기체마다 다름.
3. **기본 스탯** — 최대 체력, 이동 속도, 충돌 크기.
4. **모듈 배치** — 어떤 모듈이 몇 개, 어디에 있는지 (고정).

주포·궁극기의 강화는 **기체 레벨**로 한다 (파츠 레벨과 별개).

### 3.1 기체 방향 (확정)

- **기체는 회전하지 않는다. "전방"은 언제나 화면 위쪽(수직 전방)이다.**
- 어느 방향으로 이동하든 기체 그림과 주포 방향은 위쪽 고정이다.
- 모든 모듈의 발사 방향(4.1 표)도 이 고정된 위쪽을 기준으로 한다. 후미 = 언제나 화면 아래쪽.
- 적은 사방에서 오므로, 옆·뒤 방향은 **날개끝·후미·상부 모듈 배치로 막아야** 한다. 이것이 파츠 배치의 전략적 의미다.

## 4. 모듈 배치 (v1: 모든 기체 공통)

```
                 ▲ 전방 (항상 화면 위쪽, 기체는 회전하지 않음)
                 │
            [ 주포 ]                 ← 기체 고유, 탈착 불가
                 │
 [W1 날개끝 L] ─ [W4 상부] ─ [W1 날개끝 R]   ← W1은 좌우 한 쌍 = 슬롯 1개
                 │
           [W2 동체 하부]
                 │
            [W3 후미]
                 │
                 ▼ 후방 (항상 화면 아래쪽)

 보조 슬롯:  [S1]  [S2]  [S3]        ← 위치 개념 없음
```

- **무기 모듈 4개**: W1 날개끝(쌍), W2 동체 하부, W3 후미, W4 상부
- **보조 슬롯 3개**: S1~S3
- 모듈 하나에는 파츠 하나만. 비워 둘 수 있다.

### 4.1 무기 모듈 프로파일 (위치별 성능 배율)

| 모듈 | 발사 방향 | 공격력 | 발사 속도 | 폭발 범위 | 발사 수 | 기타 |
|---|---|---|---|---|---|---|
| W1 날개끝 (쌍) | 전방, 바깥쪽 15° 사선 | ×0.7 | ×1.2 | ×0.8 | ×2 (좌·우) | 측면 커버 |
| W2 동체 하부 | 전방 직선 | ×1.4 | ×0.7 | ×1.3 | ×1 | 관통 +1, **지상 타격 가능** |
| W3 후미 | 후방 60° 부채꼴 | ×0.6 | ×1.0 | ×1.0 | +2 (확산) | 후방 커버 |
| W4 상부 | 360° 자동 조준 (최근접 적) | ×0.6 | ×1.0 | ×0.9 | ×1 | 사거리 ×0.8 |

→ 정리: **날개끝 = 넓고 빠르게, 하부 = 강하고 묵직하게, 후미 = 뒤를 막는다, 상부 = 약하지만 어디든.**

## 5. 파츠 (Part)

### 5.1 무기 파츠 카테고리

| 카테고리 | 변하지 않는 기본 속성 | 모듈이 바꾸는 것 |
|---|---|---|
| 건 (`gun`) | 탄환 종류, 속성, 탄속 계열 | 방향, 발사 수, 연사, 공격력 |
| 미사일 (`missile`) | 유도 방식, 폭발 속성, 높은 위력·낮은 연사 | 방향, 발사 수, 재장전, 폭발 범위 |
| 드론 (`drone`) | 드론이 가진 고유 무기, 드론 체력 | 편대 위치, 드론 무기의 배율 |

- 모든 무기 파츠는 **4개 무기 모듈 어디에나** 붙일 수 있다.
- 기획 용어와의 관계: **"윙건" = 건 파츠를 날개끝에 붙인 것, "후방 건" = 건 파츠를 후미에 붙인 것.**
  즉 윙건·후방건은 별도 파츠가 아니라 "건 + 위치"의 결과다.
- 이후 레이저 등 카테고리를 추가해도 같은 규칙을 따른다.

### 5.2 카테고리 × 모듈 동작표 (구현 기준)

|  | W1 날개끝 (쌍) | W2 동체 하부 | W3 후미 | W4 상부 |
|---|---|---|---|---|
| **건** | 좌우 2정이 바깥 사선으로 연사 (= 윙건) | 1정, 전방 직선 고위력·관통 | 후방 부채꼴 3갈래 (= 후방 건) | 회전 포탑, 최근접 적 자동 조준 |
| **미사일** | 좌우 교대 발사 소형 유도탄, 빠른 재장전·작은 폭발 | 대형 1발, 느린 재장전·큰 폭발, 지상 타격 | 뒤로 발사 후 후방 적 추적 | 수직 발사 후 주변 적 여러 곳에 낙하 |
| **드론** | 기체 좌우에 1기씩 편대, 측면 적 사격 | 기체 앞에서 선행 비행, 전방 요격 | 꼬리를 따라오며 후방 적 요격 | 기체 주위를 공전(오비트) |

동작 이름은 데이터로 지정한다 (예: 드론 → `formation_side` / `lead` / `trail` / `orbit`).

### 5.3 보조 부품 (보조 슬롯 S1~S3)

무기가 아닌 공격 보조 또는 방어 보조 부품. **위치 효과 없음.** 같은 종류는 중복 장착 불가.

| 구분 | 예시 부품 | 효과 |
|---|---|---|
| 방어 | 보호막 발생기 | 주기적으로 보호막 생성 |
| 방어 | 수리 포드 | 주기적으로 체력 회복 |
| 방어 | 보강 장갑 | 받는 피해 감소 |
| 공격 보조 | 표식 센서 | 표식된 적에게 피해 증가 |
| 공격 보조 | 축전 포드 | 궁극기 에너지 충전 속도 증가 |
| 유틸 | 자석 모듈 | 경험치 보석 회수 범위 증가 |
| 유틸 | 보조 추진기 | 이동 속도·순간 가속 |

## 6. 레벨업 (성능 개선)

1. **파츠마다 각자 레벨**을 가진다 (`Lv1 ~ LvN`). 레벨은 파츠에 붙어 있고, 모듈을 옮겨도 유지된다.
2. 레벨이 오르면 파츠의 기본 수치(공격력, 연사, 폭발 범위, 발사 수 등)가 오른다.
3. 특정 레벨(예: Lv5, Lv10)에서 **추가 효과**를 얻을 수 있다 (예: 발사 수 +1, 관통 +1).
4. 레벨은 파츠의 **기본 속성을 바꾸지 않는다.** 건이 미사일이 되지 않는다.
5. 기체 레벨(주포·궁극기)과 파츠 레벨은 완전히 별개다.

## 7. 최종 수치 계산 (계산 순서 고정)

```
1) 파츠 기본값   = part.levels[현재레벨]
2) 모듈 배율     = mountProfile (4.1 표)
3) 추가 보너스   = 보조 부품 % + 전투 중 강화 %

최종 공격력   = 기본.damage    × 모듈.damageMul   × (1 + 추가보너스)
최종 발사속도 = 기본.fireRate  × 모듈.fireRateMul × (1 + 추가보너스)
최종 폭발범위 = 기본.aoe       × 모듈.aoeMul      × (1 + 추가보너스)
최종 발사수   = round(기본.count × 모듈.countMul) + 모듈.countAdd + 추가발사수
최종 방향     = 모듈.direction (파츠는 방향을 정하지 않음)
```

이 계산은 **한 함수에서만** 한다. 예: `resolvePartStats(part, level, mountProfile, bonuses)`.

## 8. 전투 중 성장과의 관계 (서바이버 요소)

| 구분 | 어디서 | 무엇이 | 유지 |
|---|---|---|---|
| 영구 성장 | 격납고(전투 밖) | 파츠 장착·해제·위치 변경, 파츠 레벨업, 기체 레벨업 | 영구 저장 |
| 전투 중 성장 | 전투 중 레벨업 카드 | **현재 장착된** 파츠 강화, 주포 강화, 패시브 | 해당 판에서만 |

- 전투 중에는 파츠를 새로 붙이거나 위치를 바꾸지 않는다 (기본값, 9장 Q4 참고).
- 전투 중 레벨업 카드는 장착된 파츠 목록에서 뽑는다. 비어 있는 모듈의 카드는 나오지 않는다.

## 10. 화면 표시 규칙

- **쌍 모듈(W1)은 슬롯 1개, 기체 그림에는 2개**로 그린다. UI 슬롯 목록에서는 1칸.
- 파츠의 그림과 발사 시작점은 모듈의 `anchors` 좌표를 쓴다.
- 장착 화면에서 파츠를 모듈에 올리면 **"이 위치에서의 성능"** 을 바로 보여준다
  (발사 방향 그림 + 공격력/연사/발사 수/폭발 범위 변경 전·후 수치).
  → 플레이어가 "위치에 따라 성격이 바뀐다"를 눈으로 이해하게 하는 핵심 UI.
- 주포와 궁극기는 기체 정보 영역에만 표시하고, 파츠 슬롯처럼 보이게 만들지 않는다.

### 10.1 아트 규칙 (확정, 2026-10-21)

**① 완전 탑뷰 (정수직 위에서 본 모습)**
- 기체·파츠·모듈 그림은 모두 **바로 위에서 내려다본 정사영**으로 그린다. 원근, 비스듬한 각도, 측면이 보이는 표현은 금지다.
- **총구 구멍(총열 끝의 원형 개구부)이 보이면 절대 안 된다.** 총열은 위에서 본 길쭉한 직사각형·막대 실루엣으로만 표현한다.
- 이유: 파츠를 여러 위치에 붙이고 회전·좌우 반전하므로, 투시가 들어간 그림은 위치가 바뀌는 순간 어색해진다.
- 파츠 스프라이트는 **위쪽(전방)을 향한 기본 자세**로 그리고, 방향은 코드에서 회전시킨다. 회전 중심(pivot) = 모듈 소켓 중심.

**② 모듈 장착부(소켓)는 고유한 모양의 부품이다**
- 소켓은 기체 그림에 그려진 고정 부품이고, **비어 있을 때도 보인다.** 무기는 그 위에 겹쳐 붙는다.
- 소켓 그림과 파츠 그림은 **별도 레이어(별도 스프라이트)** 로 둔다.
- 위치별 소켓 모양 (기본안, 모양 자체는 변경 가능):

| 모듈 | 소켓 모양 |
|---|---|
| W1 날개끝 (쌍) | 마름모 메카닉 박스 (좌우 대칭 한 쌍) |
| W2 동체 하부 | 가로로 긴 직사각형 레일 슬롯, 모서리 볼트 4개 |
| W3 후미 | 굵은 원형 테두리 안에 검은 구멍 3개가 난 원형 모듈 |
| W4 상부 | 육각형 회전 베이스 (중앙 축 + 테두리 구멍) |
| 보조 S1~S3 | 기체 그림에는 없음 (UI 슬롯만) |

**③ 화풍**
- 탕탕특공대 계열: 굵은 어두운 외곽선, 선명한 채도, 단순한 셀 음영.
- 단순하지만 **둥글둥글하지 않다.** 각진 패널, 메카닉한 경계선(패널 라인), 의미 없는 작은 점(리벳·볼트 구멍)을 어느 정도 넣는다.
- 복잡한 실사 메카닉은 금지다. 작은 화면에서도 실루엣이 바로 읽혀야 한다.

## 12. Codex 구현 규칙

### 반드시
1. 장착 정보는 `Loadout` 하나에만 저장한다. 위치 하나 = 모듈 하나 = 파츠 하나.
2. 위치별 차이는 `mountProfiles` / `behaviorByMount` **데이터**로만 표현한다.
3. 최종 수치는 `resolvePartStats()` 한 곳에서만 계산한다 (7장 순서 고정).
4. 파츠 레벨은 파츠 인스턴스에 저장하고, 위치를 옮겨도 유지한다.
5. 기체를 바꾸면 그 기체의 `Loadout`을 불러온다.

### 금지
1. 장비 슬롯과 파츠 슬롯을 따로 두는 것 (두 시스템 병존 금지).
2. 두 시스템이 같은 위치를 공유하는 것.
3. 파츠 코드 안에 `if (mount == "wing")` 같은 위치 분기를 쓰는 것.
4. 주포·궁극기를 파츠 인벤토리나 슬롯에 넣는 것.
5. "윙건", "후방 건"을 별도 파츠 ID로 만드는 것 (건 + 위치의 결과일 뿐).
6. 모듈 배율이 파츠의 기본 속성(탄 종류, 속성, 유도 여부)을 바꾸는 것.

## 13. 완료 확인 기준

1. 같은 건 파츠(Lv3)를 W1→W2→W3→W4로 옮기면: 좌우 사선 2발 → 전방 고위력 1발 → 후방 3갈래 → 자동 조준 포탑으로 바뀐다. 탄 모양·속성은 그대로다.
2. 그 파츠를 Lv4로 올리면, 네 위치 모두에서 수치가 같은 비율로 오른다.
3. 지상 적은 W2 동체 하부에 붙은 파츠와, 위치와 관계없이 미사일 파츠만 맞힌다. 다른 경우(예: 날개끝 건)는 지상 적을 통과한다.
9. 기체가 좌·우·아래로 이동해도 기체 그림과 주포는 화면 위쪽을 향한 채 회전하지 않는다.
4. 모듈은 비워 둘 수 있고, 주포·궁극기는 떼어 낼 UI가 없다.
5. 보조 슬롯에 같은 종류를 두 개 넣으려 하면 거부된다.
6. W1은 UI에서 1칸, 기체 그림에서는 좌우 2개로 보인다.
7. 저장 후 다시 불러와도 장착 구성과 파츠 레벨이 그대로다.
8. 전투 중 레벨업 카드에 비어 있는 모듈 관련 카드가 나오지 않는다.
