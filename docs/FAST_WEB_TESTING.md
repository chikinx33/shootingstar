# 빠른 웹테스트와 배포

이 문서와 `AGENTS.md`의 빠른 정책이 기본이다. 화면과 최종 답변에는 `v12.14.0`처럼 버전명만 표시하며 `+빌드번호`는 내부 Flutter 메타데이터에만 남긴다.

## 전체 테스트

2026-10-26 사용자 요청으로 옛 기능을 검사하던 실패 테스트를 정리했다. 이제 `flutter test` 전체가 모두 통과하며 약 4분 걸린다. 큰 변경 뒤에는 전체를 **한 번만** 돌리면 되고, 변경 전 코드로 다시 돌려 비교할 필요가 없다. 실패가 나오면 그것은 이번 변경 때문이다. 기능을 없애거나 바꾸면 같은 패치에서 해당 테스트를 고쳐 전체 통과를 유지한다.

## 기본 명령

기본 소스 점검과 실제 웹 실행을 구분하며, 필요 없는 검사를 자동으로 붙이지 않는다.

```powershell
# 가장 빠른 기본 점검: 버전+소스 계약. Flutter SDK/빌드/브라우저 불필요
.\tools\run.ps1 test
python tools/quick_web.py --checks-only

# 특정 파일에서 이름에 해당 문구가 있는 테스트만 실행
.\tools\run.ps1 test -TestFile test/<관련>_test.dart -TestName '<테스트 이름 일부>'
python tools/quick_web.py --checks-only --test test/<관련>_test.dart --test-name '<테스트 이름 일부>'

# 실제 화면/출격 확인 또는 배포: 한 번만 실행, 같은 빌드는 재사용
python tools/quick_web.py
.\tools\run.ps1 quick-web
python tools/quick_web.py --version major.minor.patch+build --deploy
.\tools\run.ps1 deploy-web -Version major.minor.patch+build

# 컴파일만 필요할 때: 내용이 같으면 기존 빌드 재사용
.\tools\run.ps1 build-web

# 전체 분석+Flutter 회귀는 명시적으로 요청할 때
.\tools\run.ps1 test-full
```

- 일반 UI: 320px 한 조건과 변경 화면 1회. 관련 위젯 검사가 필요하면 파일 1개/이름 필터로 조건 1개를 고른다. 이미 통과한 다른 UI 파일을 함께 반복하지 않는다.
- 공통 변경의 확산 위험/실패 재현이 있으면 관련 화면만 글자 확대/다른 폭으로 추가한다. 8조건은 기본 자동 실행이 아니다.
- 전투·보상·저장 변경은 관련 모델 파일을 검사한다. 전체 회귀는 대규모 통합/출시 전 또는 명시적인 요청으로 분리한다.
- `--analyze`/`-Analyze`는 선택 사항이다. 기본 점검에 전체 분석을 붙이지 않는다. 분석기는 `dart analyze lib`를 쓴다.
- `--checks-only`는 소스/명시한 테스트 검사다. 빌드·브라우저 검증을 통과했다는 뜻이 아니며 보고서에 건너뛴 범위를 기록한다. 배포/빌드/verify 모드와 섞을 수 없다.
- `--test-name`은 Flutter `--plain-name`의 부분 문자열 필터다. `--test` 없이 쓰면 오류로 중단한다.
- 패치마다 버전명과 내부 빌드 번호를 모두 올린다. 이미 빌드한 같은 버전을 재확인/재배포할 때는 `--version`을 생략한다. `--build-only`는 로컬 컴파일용이고 `--deploy`와 함께 쓸 수 없다.
- 빠른 소스 점검의 시간을 전체 웹 빌드/배포 시간으로 제시하지 않는다.

기본 순서는 **버전 동기화 → 소스 계약 → 변경 시 정식 웹 빌드 → 320px 실제 로비/출격/정지 확인 1회(로비에는 버전이 없고 옵션 헤더에 컴파일된 버전이 보이는지 확인) → 선택한 경우 업로드 → 활성 배포 100%/API 확인**이다. npm predeploy가 최신 빌드·버전 검사를 한 번 수행하므로 직전에 같은 검사를 따로 반복하지 않는다. 로컬 단독 실행은 업로드 대신 빌드 검사를 수행한다.

`lib`, `web`, `assets`, pubspec/lock, 패키지 구성, SDK 메타데이터와 실제 빌드 출력의 내용 해시를 비교한다. 문서나 서버 코드만 바뀌면 클라이언트 컴파일은 재사용할 수 있다. 그림 교체, 버전 변경, 다른 진입점으로 빌드 덮어쓰기, 출력 파일 누락, SDK 변경은 재사용을 차단한다. `tools/qa/test_web_build_state.py`가 이 중 핵심 네 경우를 임시 파일로 확인한다.

## 검사를 확대할 때

| 변경 범위 | 추가할 검사 |
|---|---|
| 문서·배포 도구·버전 문자열 | 빠른 기본 경로만. 도구 변경은 해당 도구의 짧은 검사 |
| 한 화면의 UI/그림 | 그 화면 관련 위젯 테스트/실제 화면만 |
| 공통 레이아웃·글자·스크롤·내비게이션 | 기본 320px 1조건. 확산 위험/실패가 있을 때 해당 화면만 다른 폭·글자 확대 추가 |
| 전투·보상·저장·경제 규칙 | 관련 엔진/모델 테스트. 여러 시스템에 걸치면 전체 테스트 |
| 대규모 통합 변경·정식 출시 전 | 전체 회귀 검증. 일반 테스트 패치와 분리 |

통과 뒤 새 변경이나 실패 원인이 없으면 다시 검사하지 않는다. 일반 배포에서 미실행한 전체 회귀를 "모두 통과"로 보고하지 않는다.

## 제한 시간과 증거

분석 45초, 관련 Flutter 테스트 120초, 빌드 180초, 짧은 웹 실행 45초, 배포 120초, 배포 조회 30초로 제한한다. 시간 초과 시 해당 명령의 자식 프로세스만 중단하고 실패를 기록한다. 무응답 분석기를 반복 실행하지 않는다. 실패하면 수정한 원인과 필요한 검사만 다시 실행한다.

공개 파일이 Access 로그인으로 이동하면 한 번 기록하고 멈춘다. 공개 화면/해시를 확인한 것으로 보고하지 않는다. 보안 설정은 변경하지 않는다. 활성 Worker와 API health는 별도로 확인한다. 배포 시 이 프로젝트의 성공 보고서에서 기존 Access 차단 근거를 자동 재사용한다. 직접 지정하려면 `--access-blocked-report .local/quick-web/<이미 확인한 실행>/report.json`을 붙인다. 이 옵션은 공개 UI 검증을 통과했다는 뜻이 아니다.

업로드가 성공했는데 배포 후 확인만 실패했으면 **빌드·검수·업로드를 반복하지 않는다.** 보고서의 Worker ID로 `python tools/quick_web.py --verify-only <Worker-ID>`를 실행해 남은 확인만 재개한다. 새 배포 직후 기본 health URL이 이전 버전을 반환할 수 있어 확인 URL에 고유 쿼리를 붙인다. 버전 전파가 늦을 때만 최대 2초의 짧은 대기를 허용한다.

실행 단계별 시간/로그는 `.local/quick-web/<실행 시각>/report.json`, 마지막 실행은 `.local/quick-web/last-run.json`에 저장한다. 짧은 웹 화면과 결과는 `tools/qa/evidence/quick-web/<버전-빌드>/`에 두 장과 `smoke.json`으로 남긴다. 서버 계정·사용자 브라우저 저장소에는 쓰지 않는다. Android APK는 빌드하지 않는다.
