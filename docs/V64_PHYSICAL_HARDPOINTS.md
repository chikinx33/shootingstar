# v10.0.64 기체 비율과 실제 장착 슬롯

## 문제와 변경

v63은 슬롯 ON에서 부품을 지우고 본체만25%로 그렸으며, OFF와 다른 좌표/목록으로 장비를 배치했다. 본체의 최대2.1배 높이에 지원 장비를 배치하고 부품 폭을44~60%로 사용해 기체 실루엣이 가려졌다.

- 원본3종의 탑뷰 기수/날개/엔진 패드를 확인하고 공통 AircraftGeometry에 기체별 좌표를 정의했다. 본체 전투 단위는100, 전투 배율은0.5다. 피해/주기/조종/충돌 판정/저장 스키마는 유지한다.
- 주포24%, 보조24%, 날개26%, 후방22%, 지상20%, 장갑20%, 지원27%, 센서/코어/벨트18%, 추진기24%다. 지원은 본체 주변1.05/1.24 높이로 옮긴다. 코드 연결선은 복구하지 않는다.
- AssemblyViewport 하나가 실제 조립물의 원점/배율을 정한다. 눈 ON/OFF에서 동일한 전체 조립물을 그리며 ON만 실제 스프라이트 경계 위에 슬롯 테두리를 추가한다. 슬롯용 복제 아이콘과 임의 격자/스크롤은 없다.
- 실제 PNG의 종횡비/장착 피벗/좌우 반사를 사용해 AssemblySocket.rect를 구한다. GearArt와 모듈 페인팅도 같은 mountedRect 규칙을 사용한다. 쌍으로 장착되는 선체/날개/엔진은 양쪽 부품에 같은 논리 슬롯을 연결한다.
- 48px 터치 영역을 가장자리 안에 확보하도록 같은 미리보기 배율을 제한한다. 밀집한 터치 영역은 부모 입력에서 실제 부품 중심까지 거리를 비교해 선택한다. 접근성은 슬롯별 이름과 장착 동작을 제공한다. 비어 있는 지원/선택 무장은 원래 장착점에서 추가할 수 있다.
- 기존 보유 장비 목록→특성→실제 장착/저장, 초록▲/빨강▼, 무장 반동/미세 지연 추종을 유지한다. 실제 부품이 바뀌면 새 스프라이트의 경계로 슬롯도 함께 바뀐다.

## 검증

기체3종×장비32종의 장착 사각형과 좁은/넓은 미리보기 경계, 눈 전환 전후 동일한 조립물/화면 사각형, 실제 위젯 슬롯 중심·폭·높이 일치를 검사한다. 장착/지원 이동/저장, 전투 포구/표적/8분 제한 검사 및320px 로비를 관련 검사로 사용한다. 최종 웹 실행/배포 근거는 quick-web 보고서에 기록한다. Android APK는 빌드하지 않는다.

검증 결과: 관련13개 검사와320px 고정 로비 검사가 통과했다. 실제 웹320px에서는 눈/장비 특성/장착/가이드/출격/일시정지를 확인했고430px에서도 동일한 기체와 공간 슬롯을 확인했다. `.local/lobby-v64/physical-layout.png`는3종 실제 조립 렌더, `lobby-430.png`/`slots-430.png`는 큰 휴대폰 실제 웹 비교다.

웹 빌드/배포 보고서: `.local/quick-web/20261021-051424-600720/report.json`. Worker `20b7d2aa-8f0b-4ecc-af28-2230e1b2ea14` 활성100%, API 버전10.0.64 확인. 공개 정적 화면의 Access 인증 차단은 기존 근거를 재사용했다. 로컬 정식 웹 화면 검증과 활성 배포/API 증거를 구분한다. 실제 결제/보상 광고는 이번 작업 범위 밖의 기존 미완료 출시 항목이다.
