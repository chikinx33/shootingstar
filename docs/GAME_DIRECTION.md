# 수호묘 특공대 공통 게임 방향

이 문서는 **지금 적용되는 규칙만** 둔다. 옛 버전의 기체·화면·그림·설계 기록은 삭제했으며 참고하거나 되살리지 않는다. 그림·UI는 `UI_DESIGN_SYSTEM.md` 맨 위의 '현재 그림만 사용' 규칙을 따른다. 아래는 앞으로의 설계 기준이며 모든 기능이 이미 구현되었다는 뜻은 아니다. 구현 상태는 실제 코드에서 확인한다. Codex와 Claude Code에 똑같이 적용한다.

## 정체성·세계관

- 게임 이름(v12.12.0 사용자 확정): 한국어 **수호묘 특공대**, 영어 **Purrtectors**(스토어 영문 전체 이름 **Purrtectors: Cat Sky Squad**). 저장 키·백업 형식 id·패키지/저장소 이름 `shootingstar`는 호환 때문에 바꾸지 않는다.
- 주인공은 집사가 돌보는 반려묘이자 지구를 지키는 **수호묘(고양이)** 다. 고양이마다 고유 기체가 있고 전방 수직 주무기는 기체 고유로 바뀌지 않는다. 기수·동체 장갑·날개·추진기를 RPG 장비처럼 탈부착하고, 무기는 기체에 실제로 붙은 칸에 단다(슬롯 규칙은 `UI_DESIGN_SYSTEM.md` v12.11.0). 펫은 다양한 병아리이며 제거·숨기지 않는다. 로비는 반측면 고양이, 출격은 탑뷰 합체. 적은 외계 진공 제국. 세계관·대왕·사령관의 초안과 확정 구분은 `CONCEPT_GUARDIAN_CATS.md`를 따른다.
- 그래픽은 래스터 그림만 쓴다. 비행체·아이템·아이콘·배경을 SVG나 코드 도형으로 그리지 않는다(사용자 승인 예외: 글로우 발사체·벡터 광채 효과). 실사용 기체 본체 그림에는 무기·방호구를 그리지 않고, 파츠는 장착 위치에 겹쳐 그릴 별도 그림으로 만든다.
- 2026-10-25 v12.9.0 사용자 확정(세계관): 인간과 고양이는 대화를 섞지 않는다. 인간이 고양이에게 도움을 청하는 표현은 금지이며, 모든 스토리·대사·집 소개는 고양이가 집사들을 몰래 돌보는 늬앙스(고양이 화자)로 쓴다. 상세: `CONCEPT_GUARDIAN_CATS.md` 2.5.
- 2026-10-25 v12.9.2 사용자 확정(파일럿): 사람 파일럿 선택은 없고 고양이가 곧 파일럿이다. 치즈=신참의 패기, 구름=고양이 눈, 까미=꼬리 방패를 처음부터 고정(카드 칸 없음, 고양이 레벨로 1~5단계). 13개 능력은 병아리 펫 후보로 엔진에 보관한다. 상세: `CONCEPT_GUARDIAN_CATS.md` 4.1.5.
- 무대는 거대한 우주가 아니라 **소소한 동네**이고 스테이지마다 집사·아이들의 **집을 지킨다**(`lib/data/houses.dart`). 각 세계는 10채짜리 동네다. 1동네 '햇살 골목'(민지네 집 → 할아버지 댁 → … → 우리 집), 2동네 '노을 언덕'(24시 편의점 → 동물병원 → 태권도장 → 세탁소 → 어린이집(정예) → 캠핑카 언니네 → 텃밭 아저씨네 → 동네 도서관 → 소방서 → 고양이 카페(최종)). 그림이 있는 동네를 넘어서는 세계는 차례로 되풀이한다(그림 house_10~19·owner_10~19·street_1). 동네 지도는 집 테크트리(위에서 아래로 길이 이어지고 집 썸네일+집주인 초상, `house_tree.dart`).

## 전투

- 고정 화면 세로 슈팅이다: 카메라 고정·고양이는 화면 안에 갇히고, 거리 타일을 지나 집이 보스와 함께 내려오는 세로 스크롤 탑뷰 지도(`FlightSceneArt.paintHouse`). 화면 양옆 56px 확장+카메라 좌우 이동. 환경 위험은 집 스테이지에서 끈다. 보스 전에는 구름이 화면을 덮는 사이 보스 집 지도로 바뀐다(거리와 집 그림을 이어 붙이지 않음).
- 적은 위·옆·뒤에서 들어오는 **편대 웨이브**(V자·뱀·가로지르기·원·비·호버·급강하·후방, 동시 최대 32, 6웨이브마다 숨 돌리기, 편대 전멸 보너스, `house_waves.dart`). 일반 적기 크기×1.3·체력×1.4, 작은 적기는 판정은 그대로 두고 그림만 3.6배 반경(중형 3.0)으로 키운다. 적 총알 그림은 판정보다 크게(약 1.5배) 그린다.
- 2026-10-25 v12.9.8 사용자 지시(적 공격 패턴은 임의로 만들지 말고 참고 슈팅 APK를 철저히 분석): Wing Fighter의 탄막 프리셋·보스 분석 `WING_FIGHTER_ENEMY_PATTERNS.md` 수치로 만든 데이터 기반 탄막 엔진(`lib/game/danmaku.dart`, 데이터 `danmaku_patterns.dart`)을 쓴다. 일반 적은 역할별 N1~N12(돌진기는 쏘지 않음, 기뢰병은 기뢰), 중간 보스는 집마다 M1~M6 중 하나에 기본/강화/광폭 템포 사다리, 최종 보스는 집마다 B1~B11 고유 세트(3~4페이즈, 페이즈마다 부위 여러 개가 각자 주기·지연으로 발사). 저격·빔은 예고선 뒤 발사. 탄 1발 피해는 원작 계수(링 0.5, 조준 연사 0.15~0.4, 저격 최대 2.5).
- 탄 모양(v12.9.7): 퍼뜨리는 탄(부채꼴·원형·나선·탄막, 중간 보스 전부)은 둥근 구체, 조준해 쏘는 한 발은 긴 막대·바늘.
- 보스는 3유형이다(`house_bosses.dart`): 거대 함선(포탑 2·보호막 발생기 2를 부숴야 코어 피해), 탄막(회전 스프링클러 포대, `houses_v12/boss_barrage`), 결투(로봇청소기 결투기, 내 탄을 읽고 피하며 앞질러 쏨, `houses_v12/boss_duelist`). 집 스테이지에서는 옛 격벽 개폐 원형 표시를 그리지 않는다. 중간 보스 체력은 일반 적×9, 최종 보스 ×4.4(결투형 ×6.0).
- 아이템은 무작위가 아니라 편대를 전멸시킨 마지막 적기가 떨어뜨리고, 중간 보스는 전용 황금 발바닥 상자(`icons_v12/item_elite`)를 준다. 총알·미사일 성장은 드롭 아이템 전용(레벨업 카드에서 제외).
- 발사체는 그림이 아닌 **글로우 이펙트**(`glow_shots.dart`: 콩알·다이아·타원·반달·별·빔·번개·고리). 기체 고유 주무기는 글로우 타원+짧은 빛 꼬리(치즈 청록·구름 하늘색·까미 보라), 병아리 펫 탄은 주황 글로우 구체. 오라·보호막·불·얼음 띠는 코드 벡터 광채(`BattlePainter._vectorAura`)로 그린다(v12.9.6). 적 예고선은 공격형 일부만, 레이저는 얇은 빔.
- 미사일은 빔이 아니라 물체다: 고양이 미사일은 큰 눈의 짧고 통통한 고등어(`houses_v12/missile_fish`), 진공 제국 미사일은 화난 눈의 통통한 스프레이 깡통(`houses_v12/missile_spray`), 꼬리에만 작은 글로우 불꽃. 세부 묘사는 최소로 한다. 기뢰는 회전하는 분홍 위험 고리+빛나는 핵(사라지기 직전 흰색 점멸), 포탄은 떨어질 자리에 주황 고리+주황 구체.
- W3에 후방 자주포를 달면 고양이 기체의 후방포 그림이 치비형 자주포(`icons_v12/mortar_mount`, 레이어가 180° 돌아가므로 거꾸로 저장)로 바뀐다(`Profile.shipLayerAssets`).

## 조작·연출

- 조작은 두 방식이다. 기본 '손가락 따라가기'는 고양이를 손가락보다 104(화면 420 기준, 약 1.6cm) 위에 두고 아주 짧은 관성만 준다(가속 약 0.045초, 마지막 약 0.07초 감속, 목표를 넘지 않음 — 느린 미끄러짐 금지). 두 번째 '드래그 이동'은 민 거리×0.9/1.15/1.4만큼 이동하고 손을 멈추면 그 자리에 멈춘다(관성 없음). 상세: `V12_4_FIELD_FEEL.md`.
- 화면에서 손을 떼거나 전투 영역을 벗어나면 전투 시뮬레이션 5%, 누르면 100%다. 앱 배경 전환·명시적 일시정지는 완전 정지다. 누르고 있는 손가락이 전장 경계를 넘어도 드래그를 유지한다.
- 좌우 이동 시 파일럿(캐노피) 레이어를 중심으로 아래 레이어는 반대쪽, 위 레이어는 같은 쪽으로 최대 기체 크기의 10%까지 밀리고 몸체가 최대 10% 좁아진다. 추진 불꽃은 그림 불꽃만 쓰며(코드 분사 줄기 없음), 전진 최대 2.3배(이동속도의 0.8배만 앞으로 가도 최대), 후진 0.7배(`ShipSpriteArt.paint`의 bank·flameScale). 효과 줄이기에서는 끈다.
- 항성포(궁극기)는 글자 없는 원형 버튼(`StarCannonButton`), 오른쪽(설정 시 왼쪽) 가장자리, 전투 영역 높이 58% 지점.
- 출격 연출(v12.9.3, `lib/ui/launch_assembly.dart`의 `SortieIntro`): 우리 집 지붕(탑뷰)에 기본 기체가 앉아 있다가 이륙 → 구름이 화면을 덮음 → 구름 위에서 3단계 조립(① 기본 기체+파일럿 ② 날개+추진기 ③ 나머지 무기·장비, 부착마다 흰 번쩍임·충격 불꽃·흔들림·장착음) → '출격!' → 구름이 걷히며 전투 크기·위치로 줄어든 뒤 시작(약 4.8초, 그동안 전투 정지). 상단에 고양이 얼굴과 '{집} 지키기'·다짐. 테스트·효과 줄이기에서는 건너뛴다.
- 이어하기(전투 저장·복원)는 없다. 출격은 한 판으로 끝난다.

## 성장

- 경험치 게이지가 꽉 차면 그 순간 스킬 선택창이 열린다(v12.5.2). 레벨업 사이 숨은 대기 시간은 두지 않는다. 자석 회수·보스 연출·선택 직후에도 게이지가 꽉 차 있으면 곧바로 다음 선택이 열린다. 레벨업 빈도는 대기 시간이 아니라 `GameEngine.growthCost`와 보석 수치로 조절한다.
- 필요 경험치(v12.9.7): 첫 레벨 60, 이후 60+레벨×16. 보석: 일반 4·편대 전멸 8·정예 8×3. 보석은 1.9배 크게 그리고 근처에서만 흡수되며 천천히 흐른다(회수 반경 1.5배·흡수 거리 26).
- 무기 성장(v12.1.0): 모든 무기(주무기·기체 무기·아이템 공격)는 강화 3(수치)+진화 3(특성)+궁극(이름·그림·작동 방식 변경)으로 성장한다. 짝 보조 스킬 조건은 없다. 진화 n단계는 같은 무기의 강화 n단계 뒤에만 나온다. 같은 부품이 두 칸에 달려 있으면 덜 자란 칸만, 한 번의 뽑기에서 같은 이름 카드는 한 장만. 궁극 선택 시 슬로모션+금색 변신 연출. 상세: `WEAPON_EVOLUTION_DESIGN.md`. 카드 그림·등급 연출은 `UI_DESIGN_SYSTEM.md` v12.7.0.
- 레벨업 카드의 과장된 신무기 6종(꾹꾹 냥펀치·털실 폭탄·레이저 포인터·발톱 반달·통통 공·수염 번개, 최대 4개, `paw_weapons.dart`)도 같은 강화·진화·궁극 규칙을 따른다.
- 전투 중 획득한 일시적 성장과 전투 밖 장비·기체·병아리의 영구 성장을 구분한다. 기존 저장 데이터와 계정 진행을 보존한다.

## 음향

v12.3.0: 배경음·효과음은 고양이 컨셉으로 자체 합성한다(numpy, 외부 음원 없음: 포먼트 고양이 목소리·골골송·병아리 삐요·오르골/피치카토). 로비 '집사네 거실'·전투 '냥냥 출격'·보스곡 '진공 제국 습격'. UI 조작음은 탭바·팝업·드롭다운까지 넣고, 로비의 실제 강화/구매/보상 변화에는 성공음을 낸다. 상세: `V12_3_CAT_AUDIO.md`.

## 기체 부위 배치

기체 부위의 미세 배치(크기·위치·회전·기준점·순서)는 마스터 전용 `기체 조립 편집기`(개발자 모드 → 조절 아이콘)에서 사용자가 직접 조정·저장하고, 저장값(`assets/data/ship_layouts.json`)을 실제 게임에 반영한다. 좌우 대칭 부위는 하나로 함께 움직이고, 버튼은 위로/아래로·왼쪽으로/오른쪽으로처럼 방향 이름으로 표시한다. 기본 기체에는 날개를 그리지 않고, 날개는 한 짝을 그려 반전 복제, 추진기 불꽃은 별도 프레임 애니메이션이다. 조종석 유리 속 고양이는 묻히지 않아야 한다. 상세: `SHIP_PART_EDITOR.md`.

## 운영·출시

- 출시 플랫폼은 Android Google Play다. 상품·광고 구성은 `GOOGLE_PLAY_MONETIZATION_PLAN.md` 맨 위의 1단계 안(v12.13.0)을 따른다. 실제 과금·광고 연동은 반드시 스토어 출시 전에 구현하고 검증한다. 미완료 상태로 출시 준비 완료를 선언하거나 출시하지 않는다. 추적: `STORE_RELEASE_CHECKLIST.md`.
- 기존 진행·전투 능력치·무료 성장 수급을 유료화하지 않는다. 실제 ID가 없는 운영 설정에서는 결제·광고를 비활성화한다.
- 설정에서 한국어/English를 즉시 전환하며 기본은 한국어다. 원본 ID/수치/판정은 바꾸지 않는다. `LOCALIZATION.md` 참고.
- 개발자 모드(옵션의 버전 3초 누르기+PIN)와 테스트 공간은 일반 저장과 별도 키로 저장한다. `DEVELOPER_TEST_LAB.md` 참고.

## 설계 기준

- 게임 시스템은 탕탕특공대(Survivors-like 선택 성장·진화·영구 성장), 슈팅 플레이는 Wing Fighter의 장점을 참고한다. 원작의 자산·명칭·화면·디자인을 복제하지 않는다.
- 고양이 기체 이동, 글로우 탄·미사일·보조 무기, 명확한 피격·폭발 표현으로 슈팅게임의 시각적 정체성을 유지한다.
- 한 판 안에서는 적 처치와 경험치 획득, 레벨업 선택, 무기 강화·진화, 조합에 따른 플레이 변화가 연결되도록 설계한다.
- 웨이브의 적 구성·밀도·정예·보스 시점은 플레이어의 성장과 함께 검토한다. 선택 화면과 실시간 전투의 시간 처리를 명확히 한다.
- 무기 조합의 다양성, 이동과 위치 선정의 의미, 공격 예고와 가독성을 유지한다. 특정 조합이나 방치가 항상 최적이 되는지 검토한다.
- 적 체력을 플레이어 화력에 맞춰 몰래 늘리지 않는다. 자동 시뮬레이션 결과를 사람의 난이도 평가로 간주하지 않는다.

## 기술 및 검증 기준

- 현재 Flutter/Dart 구조를 유지한다. 스킬의 Three.js, Java, 전용 엔진 예시를 이유로 기술 스택을 변경하지 않는다.
- 실제 콘텐츠·전투 엔진·저장 구조를 먼저 조사하고 이미 구현된 시스템을 확장한다.
- 수치 변경에는 기준값, 변경 이유, 기대 효과와 검증 결과를 남긴다. 시뮬레이션 결과와 실제 플레이 평가는 구분한다.
- 웹에서 모바일 화면과 조작, 대량 적·탄환 상황의 성능을 검증한다. 게임 완성 전 Android APK 빌드는 금지한다.
- 유료 생성·외부 API·크레딧 소모는 제공자·모델·비용·호출 수를 제시하고 별도 승인을 받은 뒤 실행한다.

## 스킬 선택

1. `roguelike-game-designer`: Survivors-like / Bullet Heaven 기준으로 선택 성장, 무기 진화·시너지, 웨이브, 영구 성장 설계에 사용한다. 턴제 던전 규칙을 자동 적용하지 않는다.
2. `space-shooter`: 기체 슈팅과 서바이버 성장 구조의 결합을 참고한다. 원본의 `assetgen` 명령이나 `shipshit-engine` 설치는 실행하지 않는다. 원본 자산 생성 절차 대신 프로젝트의 기존 작업 절차를 사용한다.
3. `game-balance`: 무기 효율, 비용 대비 성장, 선택지의 우열, 난이도와 보상을 검토한다. 예시 임계값과 대전 승률 목표를 이 게임의 확정 규칙으로 취급하지 않는다.

모든 작업에 세 스킬을 동시에 읽을 필요는 없다. 작업 범위에 필요한 스킬만 적용하며, 외부 스킬의 추가 스킬 링크는 자동 설치 승인이 아니다.
