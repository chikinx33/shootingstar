## 재현한 결함과 수정

### 처치 직후 결정 수가 저장 허용량을 초과

이전 엔진은 보급 갱신 시점에만 결정1400개 초과분을 경험치로 합쳤다. 같은 프레임 뒤쪽에서 처치 결정이 새로 생기면1401개 이상인 상태로 자동 저장될 수 있었다. 읽는 쪽은1400개를 상한으로 검사하여 `Too many actors`로 거부했다. 최종 보스 격파 연출로 먼저 반환하는 프레임도 같은 문제가 있었다.

처치 처리가 끝난 프레임에도 기존 초과 경험치 합산을 적용한다. 정상 프레임 종료 시 항상1400개 이하이며 초과분의 경험치 계산식과 기존 성장/보상은 유지한다. 예전의 정상 초과 상태는4096개 이내의 제한된 범위에서 읽어 기존 경험치 규칙으로 정리한다. 로컬 저장 전체2MiB 제한과 그 밖의 유효성 검사는 유지한다.

### 자석 연속 회수 중 저장 복원 실패

회수 중인1400개에 새 자석이20개를 더 붙이면1420개가 저장되지만 복원 상한은1400개여서 실패했다. 이제 상한 초과분은 기존 회수 빛에 경험치 값을 합쳐 표현한다. 새 경험치를 미리 지급하거나 버리지 않고 해당 빛이 기체에 도착할 때 지급한다. 상한 이하의 기존 경로/도착/잔광/성장 선택 순서는 유지한다. 초과 상태에서 합쳐진 결정의 개별 도착 시각은 대표 빛의 시각을 따른다. 이전 버전의 제한된 초과 저장도 같은 방식으로 복구한다.

`endurance_pickup_test.dart`는 두 실패의 수정 전 로그, 경험치 보존, 최종 격파 저장, 구버전 초과 복원과 과도한 크기 거부를 확인한다. 원본 소스와 실패 기록은 `.local/endurance-v34/before/`, `pickup-before.log`에 남겼다.

### 자석 회수의 반복 그리기 비용

전장에 놓인 결정은 기존 그림 캐시를 사용했으나 회수 중인 결정은 같은 PNG를 매 프레임 개별 구성했다. `ResolutionVfx.absorption`에도 `BattlePainter`의 기존14px 결정 그림 캐시를 연결했다.1400개 모두의 위치·개수·꼬리·경험치·충돌·필수 예고와 시계를 유지하며 원본 PNG는 수정하지 않았다. 효과 축소도 이용자 설정대로 따른다.

`projectile_render_cache_test.dart`는 일반/효과 축소에서1400개 회수 결정을 원래 경로와 픽셀 비교하고 체크포인트가 바뀌지 않는지 확인했다. 기존 허용 오차(평균 채널 차이0.12 미만,8 이상 차이 채널0.1% 미만)를 통과했다.

## 정식 화면의 전체 흐름·실시간 연속 검사

검사 생성 로컬 체크포인트와 격리된 Chrome 컨텍스트로 실제 정식 앱을 연다. 사용자 브라우저 저장/온라인 계정은 건드리지 않고 API 요청을 차단한다. 준비된 후반 상태는 자연 플레이 승률 검사와 구분한다.

- 전체 흐름: 출격 이어하기→성장 선택/재추첨→일시정지/통계(시간 정지)→저장 후 로비→새로고침/정지 복원/특화 유지→보스/승리/보상1회→다음 항로→중도 정산/성장 귀환.
- 연속 검사: 정식 Home/Battle 화면과 일반 프로필 자동 저장을 사용하고 포인터를 누른 상태로10분 실제 시간을 진행한다. 보스 체력을 크게 설정해 결전과 지원군을 지속한다.30초별 프레임/JS 힙/DOM/액터/저장 크기·횟수를 기록하고 마지막 저장 후 새로고침/정지 복원을 검사한다. JS 힙 확인을 위한 주기적 명시적 GC를 기록하며 GPU/네이티브·휴대폰 발열 증거로 확대하지 않는다.

실제 ID, 대상 기기/이용자 난도, 운영 정책/연락처는 출시 전 미완료 조건으로 유지한다.
