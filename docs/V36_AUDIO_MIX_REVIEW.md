# v10.0.36 실제 웹 플레이 음향 재점검

사용자 요청에 따라 로비 조작→중단 전투 이어하기→성장 선택2회→후반 보스전→승리/정산→다음 항로→정지/재개→저장 후 로비를 정식 웹 UI에서 조작했다. API는 격리401, 별도 게스트 저장소를 사용했다. 보스/보조 무기가 몰리는 구간을 확실히 만들기 위해 기존 고체력/성장된 체크포인트 fixture를 사용한다. 자연 성장 승률이나 인간의 청취 평가로 간주하지 않는다. APK 빌드 없음.

## 발견한 문제와 수정

1. 기존 효과음은 peak를 통일했지만 평균 음량은 달랐다. 주무기10종의 파일 RMS는 약 .223~.405로, 같은 재생 gain에서 약5.2dB 차이가 났다. `audio_clip_levels.dart`에 실제54개 WAV의 길이/RMS/peak를 기록하고, 재생 시 평균 음량을 보정한다. `tools/audio_mix_catalog.py --check`로 원본과 대조한다. 음원을 다시 만들면 `python tools/compose_audio.py` 뒤 `python tools/audio_mix_catalog.py`를 실행한다.
2. 반복 발사/명중·UI음이 음악을 덮었다. 보정 기준과 채널별 peak 한도를 적용했다. 효과음6채널 한도 합 .66, 음악 최대 .72×.44=.3168, 전체 합 .9768이다. 이는 앱 원본/재생 gain에 대한 최악 조건의 수학적 상한이며 하드웨어·다른 앱·장치 EQ의 보증이 아니다. 음악은 로비 .44/전투 .42×사용자 음량을 쓴다.
3. 보스 알림 일부가30~80ms에 잘렸다. 로딩 완료와 실제 클립 길이를 기준으로 중요한 채널의 재생 시간을 보호한다. 피격·일시정지·위험 등 더 중요한 알림은 우선할 수 있다. 보스 단계음 직후 위험 경보가 발생하는 경계는45ms 동안 최대1개 요청으로 합쳐 짧은 코드 파편을 재생하지 않는다. 발사/회수 등 반복음 대기열은 만들지 않는다.
4. 중요한 효과음 동안 음악을52%로 잠시 낮추고 클립 끝100ms 뒤 복원한다. Timer는1개만 유지하며 정지/음소거/장면 변경/해제 시 취소한다. 반복 발사나 회수는 음악을 계속 펌핑하지 않는다.
5. 로비/전투 음악은 단일 플레이어의60ms fade-out→곡 변경→140ms fade-in으로 연결한다. 음량/덕킹 변화도140ms로 보간한다. 음소거/배경 전환은 페이드 대기를 거치지 않고 즉시 pause하며, 로딩 중 곡은 세대 번호로 무효화한다.
6. 새 출격 시작을 `beginFlight`로 명시한다. 저장 복원으로 정지한 전투는 출격음을 내지 않고, 다음 항로/재시도는 남은 결과음/덕킹을 정리하고 출격음을 재생한다. 전투 수치·RNG·경험치·보상·저장 형식은 바꾸지 않았다.

## 측정 방법과 한계

`tools/qa/audio-playthrough.cjs`가 정식 앱을 실제 버튼/포인터로 조작하고, `audio-mix-meter.cjs`는 원래 오디오 출력 연결을 유지한 채 GainNode 뒤에 관측용 AnalyserNode만 붙인다. 별도의 자동 재생 정책 우회·가짜 재생기는 사용하지 않는다. 각40ms의4096샘플 모노 창에서 RMS/peak/동시 재생 수, 재생/중간 정지 이벤트를 기록한다.

관측한 동시 창의 peak 합은 위상에 맞춰 녹음한 실제 믹스가 아니다. 클리핑 발생률/사람의 음질 선호/Android 스피커나 오디오 포커스 평가로 표현하지 않는다. 초기 MediaStream 진단 믹스는 로비/음악 신호 누락이 있어 폐기했고 `before-*` 기록은 그 실패 근거로만 남긴다. 비교에는 직접 관측으로 교정한 `baseline-*`와 최종 기록만 사용한다. 최초 성장 선택의 접근성 이름은 설명과 합쳐져 있어 도구의 exact 검색도 prefix 검색으로 고쳤다.

최대 사용자 음량1.0, 같은 초기 checkpoint/선택 우선순위로 비교한다. 브라우저 타이밍과 플레이 반응 때문에 프레임/사운드 위상이 동일하지 않으며 아래 값은 해당 실행 표본이다. 원본: `tools/qa/evidence/audio-v36/comparison.json` 및 각 시나리오 JSON.
