### 계정 없이 동작하는 구조

- 구매·광고 기록은 게임 저장의 `content.shop`(`ShopLedger`, `lib/data/shop_ledger.dart`)에 둔다. 계정 로그인이 필요 없고, 클라우드 저장·백업에 같이 따라간다.
- 구매 흐름(`lib/services/commerce_controller.dart`): Play 결제 → 서버 `POST /api/shop/verify`가 Google Android Publisher API로 영수증을 확인(저장 없음, IP당 분당 30회) → 저장에 지급하고 저장 → 그 뒤에만 소모(소모형)·승인(1회 구매). 같은 영수증은 저장당 한 번만 지급한다(토큰 해시 보관).
- 앱 시작·복귀 때 구매 내역을 복원한다. 결제했는데 지급 전에 앱이 꺼져도 다음 실행 때 지급한다. 1회 구매 상품은 새 기기·재설치에서도 복원된다(첫 출격 꾸러미 물건은 새 저장에서 다시 지급됨).
- 서버 확인이 꺼져 있으면(`SHOP_ENABLED`, `PLAY_PACKAGE=com.raviok.purrtectors`, `PLAY_SERVICE_ACCOUNT` 비밀값) 지급하지 않고 결제를 끝내지 않는다. 3일 안에 끝내지 않은 결제는 Google이 자동 환불한다.
- 감수하는 위험: 저장 파일을 고치면 보유 상태를 만들 수 있다(혼자 하는 PvE라 허용). 영수증 토큰을 다른 저장에 옮겨 쓰는 것은 소모형은 소모 뒤 복원 목록에서 사라져 어렵다.
- 예전 계정 묶음 경로(`commerce/*`, 서버 원장·SSV)는 앱에서 더 쓰지 않는다. 서버 코드는 남아 있지만 꺼져 있다.

### 실제로 켜려면 (남은 일)

1. Play Console 결제 프로필 경고 해결(사용자).
2. AdMob에서 앱·보상형 광고 단위 생성 → `android/gradle.properties`의 `admobAppId`, `lib/services/commerce_config.dart`의 `releaseRewardedUnit`에 넣는다. 웹에 `app-ads.txt`.
3. Play Console 신고를 먼저 바꾼다: 광고 포함 "예", 광고 ID(AD_ID 권한을 다시 넣을 때 "예"), 데이터 보안(AdMob: 대략적 위치·기기 ID·앱 상호작용·진단, 구매 내역), 콘텐츠 등급 디지털 구매 "예", 개인정보처리방침에 광고·결제 추가.
4. 결제 권한이 든 AAB를 한 번 올린 뒤 위 5개 상품을 만든다(Play 규칙).
5. 서버 비밀값 `PLAY_SERVICE_ACCOUNT`(Play 권한 서비스 계정 JSON)과 `SHOP_ENABLED=true`, `PLAY_PACKAGE`를 Worker에 넣는다.
6. 라이선스 테스터로 실제 구매·복원·환불, 테스트 광고 로드·완료·닫기·광고 없음을 폰에서 확인하고 기록한다.

## 현재 코드에서 확인한 조건

v10.0.29 구현과 재현 방법은 `V29_COMMERCE_FOUNDATION.md`에 있다. SDK 어댑터·서버 원장·SSV/구매 검증·미리보기/결과 선택 흐름을 구현했으며, 실제 ID/기기 검증 완료와 구분한다.

- 패키지 후보는 기존 `com.shootingstar.shootingstar`다. Play Console의 실제 등록/소유 여부는 미확인이다. 임의로 패키지/namespace를 바꾸지 않았다.
- Android `minSdk=24`, targetSdk는 현재 Flutter 설정을 따른다. 이것만으로 출시 시점 Play API 요건이나 저사양 성능을 충족했다고 판단하지 않는다.
- 출시 서명은 구성되지 않았다. 결제/광고 SDK와 어댑터는 추가했지만 Android 실행 검증은 아직 없다. 네이티브 배포는 미완료다.
- 크레딧·장비·진행은 클라이언트 계산/클라우드 저장이다. 이 값을 유료 소유권의 근거로 사용하면 안 된다. 구매 권리는 별도의 검증된 서버 원장에 둬야 한다.
- 장비/테크 보급권의 기존 교환은180크레딧, 영구 연구 첫 단계는80크레딧이다. 기존 무료 콘텐츠와 수급을 줄여 결제를 유도하는 변경은 하지 않는다.

### 광고 보상의 현재 경제 대비 크기

`RunRewards`의 실제 공식을 대입한 비교다. 이용자의 평균 실력/수익 측정값이 아니다.

| 가정 | 기본 크레딧 |
|---|---|
|60초·60격파·보스0·미완주 |27 |
|180초·100격파·보스1·완주 |212 |
|광고 제안1회 / 하루 최대 |20 /40 |

하루 최대40은 첫 연구80의 절반, 위 완주 예시의 약19%다. 기존 정산 보상은 광고를 보지 않아도 전액 지급하고 추가분만 선택한다. 모든 패배에 광고를 띄우거나 기존 보상을 광고 뒤에 묶지 않는다. 이 수치의 장기 이용자 효용은 아직 검증하지 않았으며 실제 광고 ID가 없는 운영에서는 추가 지급이 일어나지 않는다.

## 실제 결제 구현 계약

1. 앱 계정에 연결된 비식별 구매 계정 식별자와 실제 상품 ID로 Play 구매를 요청한다. 클라이언트의 성공 콜백만으로 지급하지 않는다.
2. 서버가 구매 토큰을 Play API로 검증하고 패키지·상품·구매 상태·앱 계정 바인딩을 확인한다. `PENDING`은 대기이며 `PURCHASED` 확인 전에는 소유권을 주지 않는다.
3. 구매 토큰/거래의 고유 키로 서버 원장과 소유권을 원자적으로 기록한다. 같은 토큰의 재전송/다른 앱 계정 재사용을 방지한다. 기록 후 승인/필요한 처리를 재시도해도 지급은1회다.
4. 재설치/재로그인의 복원, 서버 알림/재조회, 환불·취소의 소유권 회수를 구현한다. 상품 유형에 맞는 승인·소비 규칙을 구분한다.
5. 유료 권리는 `Profile.exportProgress()` 업로드로 생성/복원하지 않는다. 앱 계정 삭제 시 거래 기록 처리/보관 예외는 실제 운영 정책을 확정한 뒤 연결한다.

공식 근거: [Play 구매 보안](https://developer.android.com/google/play/billing/security), [구매 상태·승인/복원](https://developer.android.com/google/play/billing/integrate?hl=en). 실제 상품/계정/API 설정과 Android 테스트 증거는 아직 없다.

## 실제 광고 구현 계약

1. 제공자가 확정된 뒤 앱 시작 때 동의 상태를 갱신하고 요청 가능 여부를 확인한다. 필요한 개인정보 선택 진입점을 제공한다. 동의 실패를 임의 허용으로 바꾸지 않는다.
2. 결과에서 사용자가 선택하면 계정·출격·노출 위치에 묶인 서버 nonce를 발급한다. 미완료 전투/체크포인트를 광고로 건드리지 않는다.
3. 제공자의 서버 검증 서명과 transaction ID/nonce를 확인한 뒤 보상 원장·일일 상한을 함께 처리한다. 클라이언트 완료 이벤트는 화면 상태만 갱신하며 자기 신고로 지급하지 않는다.
4. 광고 닫기/실패/광고 없음은 지급하지 않고 기본 정산을 보존한다. 완료 콜백/SSV가 늦게 도착해도 동일 보상은1회다. 노출/실패만으로 성공 횟수 상한을 소비하지 않는다.
5. 무료 크레딧의 현재 클라이언트 신뢰 한계를 별도로 추적한다. 광고 지급 기록이 있더라도 유료 권리를 증명하는 원장으로 혼용하지 않는다.

공식 근거: [Flutter UMP 동의](https://developers.google.com/admob/flutter/privacy), [AdMob SSV](https://developers.google.com/admob/flutter/ssv). SDK/화면/모의 콜백만으로 실제 연동 완료로 표시하지 않는다.

## 준비할 외부 자료

- Play Console의 패키지 등록 확인과 실제 상품 ID/가격/설명, Android Publisher API 접근 설정. 비밀 키는 채팅에 적지 않는다.
- 광고사 선택, 실제 앱/광고 단위 ID, 동의 메시지/대상 연령 설정과 운영 정책.
- 실제 게시자/지원 연락처, 개인정보 처리 주소, 앱 설치 없이 접근 가능한 계정 삭제 요청 주소. 기존 웹의 Access 보호는 자동 해제하지 않는다.
- 출시 서명과 현재 Play 타깃 API 요건, 테스트 계정/대상 기기. 기존 APK 빌드 금지의 명시적 변경도 필요하다.

## 사전 검사와 현재 결과

비밀 정보 없는 설정은 `release/google_play.json`, 검사는 `python tools/google_play_readiness.py --json` 또는 `tools/run.ps1 store-readiness`다. v10.0.29 현재 플랫폼/SDK2개 존재의3개 구조 항목이 확인되고13개는 `blocked`다. 종료 코드2는 이 미완료 상태를 뜻한다. SDK 존재만으로 실제 연동 검증을 통과시키지 않으며, 구조상 자료를 모두 갖춰도 `review_required`까지만 표시한다. URL 실제 접근/정책 내용/증거의 진실성/스토어 승인을 자동 판정하지 않는다.

`tools/run.ps1 build-apk`는 현재 사용자 지침에 맞춰 빌드 전에 중단한다. Android 빌드를 실행하지 않았다. 네이티브 실연동과 출시 조건은 별도 미완료로 남긴다.
