# 수호묘 특공대 UI 규격 — 필수 적용

Codex와 Claude Code는 **UI 수정 전에 이 문서와 `lib/ui/game_ui.dart`를 읽는다.** 이 문서에는 지금 적용되는 규칙만 둔다. 같은 주제에서 위에 적힌(새) 지시가 아래 공통 규격보다 우선한다. 단순히 클릭 영역만 크게 만들거나 그림을 붙이는 것으로 규격을 충족하지 않는다. 실제로 칠해진 버튼 면적, 글자, 그림, 정보의 비중을 검토한다.

## 현재 그림만 사용 (2026-10-26 사용자 지시, 최우선)

- 화면·전투에 쓰는 그림은 아래 폴더의 것만 쓴다. 이것이 이 게임의 유일한 그림이다.
  - `assets/art/menu_v13` 메뉴·재화·트로피 그림 / `ui_v13` UI 키트·배경·버튼 아이콘 / `cards_v13` 스킬 카드
  - `houses_v12` 집·거리·구름·집주인·보스·미사일 / `ship_parts` 고양이 기체 부위·보조 구슬 / `icons_v12` 전투 아이템·자주포
  - `fx_v11` 이펙트 / `shop_v1` 상점 / `cats_v11` 고양이 / `story_v11` 프롤로그 / `lobby_v11` 로비 거실
  - 새 v14 묶음 `enemies_v14`·`pets_v14`·`icons_v14` 등(적·보스·병아리·아이콘, 원본 `assets/concept/v14_*`)
  - 아직 코드가 쓰는 `icons_v11`은 남아 있는 동안만 쓰고, 새 작업의 참고나 확장 대상으로 삼지 않는다.
- 삭제한 옛 그림은 쓰지도 다시 만들지도 않는다: `lobby_v9`, `refit_v16`, `airframe_v51`, `airframe_v52`, `gear_v52`, `game_v10`, 옛 아이콘 시트를 칸으로 잘라 쓰던 방식, 코드로 그린 제트기. git 기록·`.local/`·`assets/concept/`에 남은 옛 그림이나 옛 문서의 배치를 되살리거나 참고하지 않는다. 새 그림이 필요하면 새로 생성한다.
- 모바일 게임 배치를 쓴다: 정보는 문장이 아니라 **그림 슬롯**으로 보인다. 슬롯은 큰 그림+`×수량` 배지, 상태는 슬롯 위에 겹친 표시(`받음`·`오늘`·`잠김`)로 나타낸다. 상세는 팝업 하나에 스크롤 없이 담는다. 설명 문장을 줄줄이 늘어놓는 화면을 만들지 않는다.

## 현재 화면 규칙

2026-10-26 v12.14.0 사용자 지시(텍스트 레이아웃 정리):
- 정보 글자를 같은 크기·같은 흰색 줄로 쌓지 않는다. 값에는 라벨을 붙이고(`GameTag`), 서로 다른 사실을 `a · b · c` 한 줄로 잇지 않고 칸으로 나눈다(`GameFactRow`/`GameFact`: 라벨 위·큰 값 아래). 묶음은 `GameInset`/`GameInfoBlock`(라벨 태그+굵은 본문+옅은 설명)으로 구분한다(`lib/ui/game_info.dart`).
- 색으로 정보의 종류를 나눈다(`GameTone`): 금색=핵심(이름·등급·보유), 하늘=일반 규칙·수치, 빨강=위협·경고, 초록=보상·해금, 회청=힌트·부가 설명.
- 캐릭터의 말·다짐은 크림색 말풍선(`GameQuote`, 말한 이 표시)으로 규칙·수치와 구분한다. 보상은 문장이 아니라 재화 그림 칩(`GameRewardChip`)으로 보인다. 받은 1회 보상은 흐리게 하고 ‘받음’ 태그를 단다.
- 출동 버튼은 고양이 로켓 그림(`menu_v13/launch`), 보상 안내는 발바닥 상자(`menu_v13/supply`)를 크게 넣는다.

2026-10-26 v12.11.0 사용자 지시(슬롯 = 기체에 실제로 붙은 장치):
- 슬롯은 기체 그림에 실제로 붙어 있는 장치만 둔다. 장비 4칸: 기수·동체 장갑·날개·추진기(세트 효과 2·4부위). 무기 5칸: 메인건(기체 본체 주둥이 포신, 기체 고유 주포, 고정 칸, 누르면 기체 정보·강화) · 윙건(W1, 날개 끝 포 한 쌍, 발칸) · 미사일(W2, 날개 미사일 한 쌍, 미사일 종류, 지상 공격) · 자주포(W3, 꼬리 포, 자주포·후방 발칸) · 보조 장치(S1, 가운데 구슬, 단 부품 1개의 효과만 발동). W4 상부 포탑·S2·S3·드론·보호막 장치는 없다(`mountAccepts`).
- 슬롯·팝업 아이콘은 기체에 붙은 파츠 그림 그대로 쓴다(`CatGearScreen.partSprite`, 메인건은 `ship_parts/<기체>/maingun.webp` 본체 크롭). 보조 부품 7종은 각자의 구슬(`ship_parts/orbs/<부품>.webp`, `tools/cut_support_orbs.py`)이고 장착하면 기체 가운데 구슬도 바뀐다.
- 무기 배치: 메인건 기수 위 가운데, 자주포 꼬리 아래 가운데, 미사일 왼쪽 아래, 윙건 오른쪽 아래, 보조 장치 왼쪽 위. 장비는 네 모서리.
- 옛 저장의 보호막 장치 장비는 전액 환급, 드론은 분해 값 환급, 빈 보조 장치에는 보강 장갑 Lv.1을 넣고 로비에서 한 번 안내한다(`Profile.updateNotices`).

2026-10-26 v12.10.0~1 사용자 지시(성장 화면, 중복 UI 금지):
- 같은 부품·재화를 한 화면에 여러 번 보이지 않는다. 슬롯을 누르면 팝업 하나로 가는 한 경로만 둔다.
- 성장의 장비·무기 탭은 한 화면(`CatGearScreen(weapons:)`)이다. 능력치 라벨(전투력·화력·선체·피해 감소·이동 속도·회수 범위·발동 세트) + 화면 가운데 큰 기체 + 슬롯만 둔다. 재화 판(최상단 헤더와 중복), 부위 필터 탭, 하단 보유 카드 목록은 두지 않는다.
- 탭을 바꾸면 페이지를 넘기지 않고, 지금 슬롯이 기체 쪽으로 빨려 들어가 사라지고(약 0.22초) 기체가 한 번 부풀며 다른 슬롯이 튀어나온다. 기체 크기는 두 모드에서 같다. 좌우 슬롯은 화면 끝에서 띄운다(폭의 6%, 16~32px).
- 무기 모드 라벨: 기체 이름·기체 Lv·고유 주포·궁극기·무장/보조 장착 수·보유 파츠, 누르면 기체 정보(기체 강화).
- 장비·무기 슬롯 팝업은 같은 모양: 위 `GameSlotList`(목록 최대 약 2.5줄, 처음엔 장착 중인 부품 선택), 아래 이름+2~3줄 정보, 행동은 `GameActionStrip`의 `GameActionTile`(그림 위·짧은 글자 아래, 항상 키트 알약) 한 줄. 장비 = 장착·강화·잠금·분해, 무기 = 장착/해제·강화·분해(확인 팝업).
- 병아리는 슬롯을 누르면 팝업 없이 슬롯 아래 빈 곳의 패널에 상세를 보인다. 버튼은 배치(출전·보조) 한 줄, 성장(육성·승급·호감도) 한 줄.
- 기체는 끌면 작은 범위(기체 크기의 18%, 고무줄처럼 점점 덜 따라옴) 안에서 움직이고, 놓으면 탄성 있게 제자리로 돌아온다. 전투와 같은 `ShipSpriteArt.paint`의 `bank`·`flameScale`로 입체감을 낸다.

- 공통 슬롯(`GameItemSlot`)은 높이가 모두 같다: 큰 그림 84px, 제목 두 줄(이름 · 설명, 또는 이름/단계), 상태 한 줄. 각 줄은 줄바꿈하지 않고 칸이 좁으면 줄 단위로 축소한다. 업적은 업적마다 다른 트로피 그림을 쓴다.
- 비행 가이드는 아이콘+설명 묶음을 화면 가운데 두고 글자는 왼쪽 정렬한다(`GuideTip`, `center_ui_text.py`의 유일한 예외). ‘자세히’ 버튼은 두지 않는다.

2026-10-25 v12.4.3 사용자 지시(최우선): 화면과 팝업은 휴대폰(360×720·390×844, 글자 1.0)에서 페이지 넘김 없이 한 페이지에 들어가야 하고 스크롤도 쓰지 않는다. 꼭 필요한 정보와 주요 행동만 남기고 규칙·긴 설명·세부 내역은 앱바 `?`(`InfoAction`/`showInfoDialog`, `lib/ui/info_dialog.dart`)나 ‘자세히’·‘보상’ 팝업으로 옮긴다. 선택지는 세로 타일 대신 `GameChoiceRow`/`GameCompactChoice`(`lib/ui/compact_choice.dart`)로 한 줄에 놓는다. `GamePages`의 페이지 나눔은 320×568·글자 1.3 같은 극단 조건의 최후 수단이다. 결과창·일시정지는 페이저 없는 고정 오버레이다. 화면별로 남긴 것과 팝업으로 옮긴 것: `V12_4_3_ONE_PAGE_UI.md`. 검사: `test/one_page_screens_test.dart`, `test/one_page_states_test.dart`, `test/one_page_dialogs_test.dart`, `test/result_screen_test.dart`.

## 공통 규격

단위는 Flutter 논리 px. 기기 해상도 배율을 다시 곱하지 않는다.

| 역할 | 실제 도색 높이 | 글자 | 아이콘 | 폭/사용처 |
|---|---:|---:|---:|---|
| 주요 결정 | 최소 72 | 22, 굵기 900 | 36 (그림 60) | 최대 264, 출격·재시도·계속 |
| 보조 결정 | 최소 64 | 20, 굵기 900 | 32 (그림 50) | 최대 264, 통계·귀환 |
| 일반 행동 | 최소 60 | 18, 굵기 800 이상 | 28 이상 | 목록/팝업의 작업 버튼 |
| 좁은 셀 행동 | 최소 48 | 15, 굵기 900 | 필요하면 24 이상 | `GameUi.compactButton` |
| 화면 제목 | 내용에 따라 | 28–32 | — | `GameAppBar`, 제목보다 보조 설명이 커지지 않게 |
| 본문 / 보조 설명 | 자동 높이 | 16 / 14 | — | |
| 하단 내비게이션 | 최소 88 | 14, 굵기 900 | 44 | 텍스트 배율만큼 높이 증가 |
| 공통 슬롯 | 모두 같은 높이 | 이름·설명 두 줄 + 상태 한 줄 | 84 | `GameItemSlot`, 반복 항목은 `GameSlotList`/`GameSlotRows` 최소 3열 |
| 상세/확인 팝업 | 화면 높이 이내, 한 페이지 | 제목 28 / 본문 16 | 닫기 32, 터치 48 | `GameDialog`, 폭 최대 440 |
| 획득 보상 카드 | 자동 높이 | 수량 22 / 이름 16 | 64 | `RewardGrid` |

- 주요·보조 결정은 반드시 `GameActionButton`을 쓴다. 너비/실제 높이 비율은 **4.25 이하**다. 화면을 가로로 채우려고 폭을 늘리거나 `SizedBox(width: double.infinity)`의 얇은 배너로 대체하지 않는다.
- 12px는 작은 메타데이터의 최저 한계다(전투 HUD 수치, 작은 등급 보조 표시). 본문·안내·행동 문구를 12px로 내려 공간을 해결하지 않는다. `fontSize: 6..11`은 금지한다.
- 닫기·뒤로·증감 같은 정밀 제어는 명확한 기본 글리프를 허용하며 터치 영역은 48 이상이다. 클릭 영역과 실제 도색 크기를 구분한다.
- 화면 좌우 여백 최소 12, 결정 화면 16. 버튼 사이 12, 아이콘과 문구 사이 최소 12.
- 일시정지/결과의 콘텐츠 폭은 최대 344, 행동 폭은 최대 264다. 가운데 정렬하고 좁아지면 함께 줄어든다.
- `TextScaler`를 존중한다. 행동 문구에 `FittedBox`, `BoxFit.scaleDown`, 글자 축소, 말줄임을 쓰지 않고 줄바꿈과 높이 증가로 해결한다(공통 슬롯 제목의 줄 단위 축소만 예외).
- 모든 화면의 제목·설명·버튼·입력 문구는 각 콘텐츠 영역에서 가운데 정렬한다(`tools/center_ui_text.py --check`). 정렬을 위해 글자·버튼을 줄이지 않는다.
- **리스트 항목 이외에는 스크롤을 허용하지 않는다.** 로비는 모든 주요 조작이 한 화면에 들어가는 고정 구성이다. `ListView`는 상품·보상·우편·장비·임무 등 반복 항목의 뷰포트에만 허용하며 `check_ui_contract.py`의 허용 목록을 유지한다. 새 화면을 일반 스크롤로 감싸지 않는다.
- 세로 화면 전용이다. Android는 세로 고정, 넓은 브라우저는 가운데 세로 화면으로 보이고, 모바일 웹 가로 화면에는 회전 안내를 띄우고 전투를 일시정지한다. SafeArea로 노치·하단 제스처 영역을 확보한다.
- 전투 상단은 짧은 2줄(진행·시간·정보/일시정지, 체력/레벨·경험치)만 둔다. 적 출현·보스 체력·공격 예고 같은 변동 정보는 전장 위 오버레이로 그리며 전장 사각형·카메라 원점·조종 입력을 바꾸지 않는다. 무장·특화 상세는 일시정지되는 정보 창에서 읽는다.
- 자원 숫자는 큰 값만 K/M로 표시하고 접근성 라벨에는 전체 수치를 유지한다.
- 그림은 원본 비율을 유지한다(`BoxFit.contain`, 배경만 비율 유지 `cover`). 빈 공간을 그림을 늘여서 채우지 않는다. 생성 그림에 대응하지 않는 기호는 실제 의미의 글리프를 쓰고, 관련 없는 그림으로 대체하지 않는다.
- 보상 팝업은 지급 직전/직후의 실제 증가분을 보인다. `RewardPopup`의 확인·닫기·재렌더는 지급을 실행하지 않는다. 실패·이미 받은 행동에는 획득 팝업을 띄우지 않는다.
- 공통 행동·선택·뒤로가기에는 조작음을 연결한다(`audio_feedback.dart`). 비활성 버튼·타이핑·이동/휠은 클릭음을 반복하지 않는다.
- 팝업 본문은 `Theme.textTheme.bodyMedium`을 명시적으로 상속한다. 팝업/단계 제목은 접근성 heading, 설정 스위치는 고유 이름과 상태를 제공한다.
