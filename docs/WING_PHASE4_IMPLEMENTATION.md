# 주무기 영구 소유·성장 — v10.0.5

2026-10-18. 사용자의 후속 요청으로 주무기 10종에 영구 소유·강화를 추가했다. 이전 설계안 6절의 '아직 소유/획득을 추가하지 않는다'는 단계적 권장은 이번 명시적 구현 요청으로 확장했다. 원작 코드·그림·희귀도·가챠를 복제하지 않는다.

## 테스트 동선

로비 하단 **v10.0.5** 확인 → **성장 → 장비 → 관리 → 주무기 소유·성장**. 기체 격납고의 독립 주포 선택 아래에서도 같은 화면에 들어갈 수 있다. 보유/미보유 주무기 항목만 목록으로 이동하고 상세·해금·강화·초기화 결정은 고정 페이지다.

- 기존 저장: 전에 선택 가능했던 주무기 **10종 전부 영구 보유**, 강화0으로 이전한다. 선택 주무기와 저장 편성을 그대로 유지하며 이전 비용은 없다.
- 신규 저장: 펄스를 기본 보유한다. 나머지는 각각 **300 C + 설계도3**으로 확정 해금한다. 신규 재화·희귀도·무작위 획득은 추가하지 않았다.
- 보유 주무기를 장착하고 **강화 +1**을 누른다. 현재 보유 자원·다음 비용·전후 효과를 상세에서 확인한다. 강화는 소유와 별개로 무기마다 저장한다.
- 새로고침 후 보유/강화/장착이 남는다. 출격 → 일시정지 → 전투 통계 → 현재 빌드에서 **영구 강화와 R/P/N**을 따로 확인한다.
- 강화 초기화는 확인 창을 거쳐 강화 재료를 전액 반환한다. 소유권·장착·저장 편성은 유지하며, 해금 비용은 반환하지 않는다.

로컬 `http://127.0.0.1:8797/?ui=v10.0.5`, 공개 `https://shootingstar-online.chikinx1.workers.dev/`. 공개 화면은 기존 Cloudflare Access 인증이 필요하다.

## 초기 성장 규칙

`lib/data/armament_collection.dart`의 안정 문자열 ID와 강화0~10으로 관리한다. 목록 순서와 기존 저장의 주무기 인덱스는 유지한다.

| 항목 | 자체 초기 규칙 |
|---|---|
| 강화 효과 | 한 단계당 해당 주무기 피해 +2%, 최대 +20% |
| 다음 강화 크레딧 | 현재 강화 n에서 `120 + 80 × n` C |
| 다음 강화 설계도 | `1 + n ~/ 3` |
| 강화0→10 총 투자 | 4800 C + 설계도22 |
| 초기화 | 현재 단계까지 위 비용을 합산해 전액 반환. 중복 반환 불가 |
| 자원 상한 | 반환 시 9,999,999 C 또는 설계도999,999를 넘으면 원상태로 거부. 초과분을 버리지 않음 |

해금 비용은 무기별 우열이나 희귀도 비용이 아니다. 모든 무기에서 동일하며 서로 다른 사격 방식을 확장하는 선택이다. 기존 출격/보스 보상·임무·순찰 등 재료 공급과 기존 장비/연구 지출을 공유한다. 새 보상이나 파밍 규칙은 만들지 않았다. 초도 수치는 기능 검증용이며 실제 플레이의 해금/강화 속도와 선호도를 보고 조정할 수 있다.

영구 피해 배율은 기존 `mainDamage`에 한 번만 합성한다. 일반 주포·N 발사 묶음·기존 분기·진화 주포와 그 파생 피해에 적용한다. 영혼 추적검의 정액 영혼 추가 피해/피격 방출도 같은 주무기 배율을 받는다. 전역 `damageFactor`는 바꾸지 않아 보조 무기·파일럿·펫·공용 궁극기에 전파되지 않는다. 기존 전역 장비/연구/조종사 성장과 주무기 전용 성장을 구별한다.

R/P/N은 매 출격 기존 초기값으로 시작하고 기존 아이템으로 성장한다. R3/P3/N2 진화, 다른 주무기 진화·합체, 주포 특화 선택, 6+6 슬롯·보조 융합과 전투 보상은 그대로다. 영구 강화로 해당 필드 수치나 진화 조건을 미리 지급하지 않는다. 전투 시작 시 장착 주무기와 강화 단계를 엔진에 복사하므로 다른 계정이나 장비 변경이 진행 중 전투의 수치를 바꾸지 않는다.

## 저장과 보호

최상위 `version:4`와 저장 키를 유지하고 다음 필드만 추가했다.

```json
{
  "armamentProgressionVersion": 1,
  "armamentCollection": {"pulse": 0, "shotgun": 4}
}
```

새 필드가 없는 기존 로컬/클라우드 저장은 기존 전체 선택권에 해당하는 10종 소유로 이전한다. 로컬 이전 전 원문을 `shootingstar.profile.v1.beforeArmamentProgression`에 한 번 백업하고 다시 덮어쓰지 않는다. 기존 클라우드 적용·계정 전환·충돌 선택의 기기 진행 백업과 교체 경로를 재사용한다. 새 스냅샷을 다른 계정으로 교체할 때 소유·강화는 합산하지 않는다.

알 수 없는 ID·문자/소수/음수 강화는 제외하고, 상한 초과 정수는10으로 제한한다. 기본 펄스는 항상 보유한다. 미보유/범위 밖 주무기 선택은 펄스로 정규화한다. 일반 선택과 저장 편성 적용 모두 소유권을 검사하며, 편성 실패는 현재 선택을 부분 변경하지 않는다. 편성에는 강화 값을 복사하지 않고 장착할 때 현재 강화 값을 사용한다.

해금 중복·자원 부족·미보유 강화·최대 단계·이전 단계의 오래된 강화/초기화 결정을 모델에서 거부한다. 초기화 확인 중 계정 컬렉션이 교체되면 그 확인을 적용하지 않는다. 성공한 변경은 기존 직렬 저장과 클라우드 변경 통지로 처리한다.

서버는 새 스냅샷의 마커·ID·정수 단계0~10·기본 펄스·선택 무기 소유를 검사한다. 이미 새 마커가 있는 클라우드 진행을 마커 없는 구버전 저장이 덮어쓰려 하면409와 현재 클라우드 진행을 반환한다. 기존 CAS revision 및 항로/활동/고급 성장 보호를 유지한다. 실제 과금/광고·출시 항목과는 무관하며 스토어 출시 조건을 완료한 것으로 간주하지 않는다.
